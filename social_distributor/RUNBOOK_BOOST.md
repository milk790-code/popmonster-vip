# 跨帳號互助（按讚＋留言＋自己的引流連結）

自家粉專在另一個自家粉專的貼文下**按讚，並留一則自己的話**，話後面帶
**那個粉專自己的** `https://popmonster.vip/go?src=fb-xxxxxx`。
按讚帶不進人，留言才會；來源碼不同，才算得出是哪一頁的功勞。

引擎：`app/utils/boost.py`（規則）＋ `app/scheduler/tasks.py`（執行）
畫面：帳號中控分頁底部「跨帳號互助」（唯讀，可試算）
API：`GET /api/boost/settings`、`GET /api/boost/preview?target_id=N`

## 開起來（本人操作，3 分鐘）

Railway 專案 `laudable-gentleness` → **`worker` 服務** → Variables：

```
BOOST_ENABLED=1
```

**一定要設在 `worker`，不是只設在 `api`。**
發文與互助都跑在 worker；`api` 只是頁面在讀。
（2026-08-01 的教訓：`FB_FIRST_COMMENT` 當初只設在 `api`，
於是「自動首則留言」幾個月一次都沒發過，而且完全沒有錯誤訊息。）

`api` 也設一份，是為了讓帳號中控畫面上的「總開關」顯示正確——
只影響顯示，不影響行為。

### 可調（都有預設值，不設就用預設）

| 變數 | 預設 | 意思 |
|---|---|---|
| `BOOST_MAX_SUPPORTERS_PER_POST` | 3 | 一則貼文最多幾個自家粉專出來互動（上限 8） |
| `BOOST_WINDOW_MINUTES` | 180 | 互動打散在發文後多久之內 |
| `BOOST_MIN_DELAY_MINUTES` | 25 | 最快也要等這麼久才動（別讓它看起來像機器人在守著） |
| `BOOST_CROSS_LINE` | 未設＝關 | 開了才允許跨業務線（貢丸粉專去汽美貼文下留言）。**建議永遠別開** |

每個粉專「每天最多幾次」在帳號中控裡各自設，上限 5，預設 1。

## 開之前先做一次的事

### 1. 用試算看一則真的貼文（不會發，隨時可做）

帳號中控 → 最底下「拿哪一則已發出的貼文試算」→ 填 Status board 上任一
已發出的 target ID → 「試算（只看不發）」。
會列出：哪三個粉專、幾分鐘後、各自要講什麼、帶哪一條連結，以及沒排到的原因。

### 2. 實測一次「A 粉專能不能在 B 粉專的貼文下留言」

Graph API 沒有明文禁止跨粉專留言，但權限要求是對該粉專有
MODERATE/CREATE_CONTENT task——推論在自家 57 個粉專之間成立，**但沒實測過**。
這是唯一還沒證實的一環，而且它是**對外寫入**，所以要本人按。

最省事的驗證＝**直接開起來，發一則貼文，看留言有沒有出現**。
沒出現的話，`boost.failed` 會進 audit log 並寫明缺哪個權限
（不再像首則留言那樣被 `except: pass` 吞掉）。

## 護欄（每一條都對應 Meta 政策的一句話）

Meta 咬的不是「一個人有很多粉專」——官方 CIB 定義要件是**假身分／不實資產**，
真實品牌粉專不落入。會咬的是這兩句：

1. Spam 條款：「以**人工或自動**方式，**極高頻率**地張貼、分享、**與內容互動**」
   → 寫明 manually or automatically，「我是人工點的」不能免責，**唯一變數是頻率**。
2. 「垃圾網路常常建立數百個帳號來分享**同一份**內容」
   → 同一句話散到很多粉專，就是這個形狀。

對應的實作：

| 護欄 | 對應哪一句 |
|---|---|
| 總開關預設關，且在環境變數不在頁面按鈕 | 開始寫 Facebook 是刻意決定，不是誤點 |
| 每則貼文最多 3 個粉專；每粉專每天上限 1（最多 5） | 「極高頻」 |
| 素材池空的就閉嘴，**絕不共用一句話** | 「同一份內容」 |
| 同一則貼文兩個粉專不會講同一句 | 同上 |
| 只在同一條業務線內互助 | 不相關資產一起動＝網路的形狀 |
| 打散 25–180 分鐘，且不會有兩則落在同一分鐘 | 「極高頻」 |
| 留言最少 8 個字，「推」「+1」存不進去 | 官方點名的「協同假互動留言」 |
| 計畫是決定性的（重跑拿到同樣的人、話、時間） | 重試不會疊出第二輪 |

**57 個粉專是連坐的**：Meta 帳號完整性標準明文，與已停用帳號屬同一人／
同一實體的帳號也會被停用。一支自動化闖禍，全部陪葬——這就是為什麼
上面每一條都往保守的方向設。

## 怎麼看它有沒有在動

- audit log：`boost.scheduled`（排了誰、誰被跳過）、`boost.performed`
  （真的按了讚留了言，含 comment_id）、`boost.failed`（含缺哪個權限）
- 每日上限是**從 audit log 回算**的，不是另外存一個計數器——數字隨時對得回來
- 帳號中控的互助面板會直接標出「角色設了但素材池是空的」＝那個粉專永遠不會開口
